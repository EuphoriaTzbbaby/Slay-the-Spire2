# 本地语音基本调试

Python 独立服务，使用 Vosk 中文离线识别、WebRTC VAD 人声检测、sounddevice 麦克风采集，以及 macOS `say` / Windows System.Speech 系统播报。游戏端仍负责 AI 请求、对话、快照和游戏动作。协议保持 v1。

这是基本联调版，供游戏负责人与语音组继续开发。Windows 是交付优先平台；本轮开发机为 macOS，Windows 音频尚未实机验收。

**最新临时范围（2026-11-08）：启用基础语音回复。** QQ/麦克风按钮从关闭状态开启时默认语音→语音，AI 仍保留文字并交给现有系统 TTS 播报；设置可切回语音→文字。重启游戏仍默认关闭语音。播报时屏蔽麦克风、结束后恢复，当前为基础半双工。此前 2026-11-04 已验收的是基础语音→文字；本次补上基础输出，不修改系统音量。语音组要补的能力、现有代码缺口与交付清单见[语音组对接](../docs/语音模块-接口与参数分析.md)。基础 TTS 现在接入日常开关；真实可闻性仍需播放器、输出设备和系统音量实测。

## 三种模式

游戏 F9 →「设置」→「交流方式」：

| 模式 | 玩家输入 | AI 回复 | 麦克风与播报 |
| --- | --- | --- | --- |
| 文字 → 文字 | 打字 | 文字 | 关闭连接，停止采集与播放 |
| 语音 → 文字 | QQ 开启持续对话后说话 | 文字 | 开启语音聊天后持续收音，不自动播报 |
| 语音 → 语音（保留文字） | QQ 开启持续对话后说话 | 文字 + 系统播报 | 开启语音聊天后持续收音，成功聊天回复自动入队 |

三种模式都保留打字入口、同一个模型配置和聊天历史；切换模式不会重复向 AI 提问。语音控制口令由游戏端检查并执行，不调用大模型。`暂停`、`恢复`、`到你了`等仅完整匹配；`先别暂停`作为普通聊天。

## 首次准备

安装 Python 3.11+（建议 3.11/3.12；Windows 使用 x64），在仓库根目录运行：

```bash
python3 scripts/voice_dev.py setup
```

Windows 可将 `python3` 换成 `python`。脚本建立 `voice/.venv`、安装当前包，并从 [Vosk 官方](https://alphacephei.com/vosk/models) 下载约 42 MB 的 `vosk-model-small-cn-0.22`。依赖、模型和录音不提交 Git。macOS/Windows 的 pip 包包含 PortAudio，见 [sounddevice 安装说明](https://python-sounddevice.readthedocs.io/en/latest/installation.html)。

已有模型可用服务参数 `--model 路径` 指定。下载失败时可从官方页面手动下载、解压到 `voice/models/vosk-model-small-cn-0.22/`；该目录应含 `am/final.mdl`。

准备完成后重新执行 `python3 scripts/game_dev.py install`。安装器会在本机 Mod 目录生成 `voice-launch.json`，引用当前虚拟环境、入口和模型；它不入库、不进入玩家包。此后 QQ 自动启动服务，日常无需终端。`voice_dev.py run` 仅保留给语音组独立调试。更新后重启游戏即可让游戏自启的服务使用新版代码。

macOS 开发机安装还会用 Xcode Command Line Tools 编译本机 `.local/voice-macos/SpireVoice.app`。游戏通过独立应用「尖塔语音 / Spire Voice」申请麦克风权限；首次授权后才启动后端。拒绝时图标显示不可用并提示系统设置的位置。项目在移动硬盘上时，系统也可能询问读取该磁盘的权限，以加载代码和模型。应用保留系统正常授权流程，不修改游戏签名或系统权限库。私有 FIFO 把游戏的退出传递给独立应用和 Python，正常退出或游戏崩溃都应回收；关闭 QQ 只停止麦克风并保留模型。

2026-11-04 实机排查发现：游戏原本没有声明麦克风采集能力，直接从游戏启动 Python 会被 macOS 拒绝，即使 PortAudio 返回启动成功、图标变绿，也可能没有真实输入。独立终端测试通过不能替代此路径的验收。独立应用的系统授权身份、真实模型加载、鉴权和父管道 EOF 后退出已验证；同日负责人重启游戏后反馈基础输入测试成功，具体范围见下方实机记录。

正式玩家包应包含 `SpireCompanion/voice/spire-voice.exe`（Windows）及其依赖、`voice/models/vosk-model-small-cn-0.22/` 模型。Mod 优先使用附带的运行时，不依赖系统 Python。语音组交付同平台可执行目录后，用 `python3 scripts/package_release.py --voice-runtime <目录>` 打包；当前未产出并验收 Windows 语音二进制，不把纯文字包描述成免 Python 语音包。

## 先检查输入，再进入游戏

```bash
python3 scripts/voice_dev.py devices
python3 scripts/voice_dev.py test-mic
```

- `devices`：列出输入输出设备。
- `test-mic`：打开麦克风，最多等 15 秒，识别一句话后退出，不保存录音。
- 指定输入设备：`python3 scripts/voice_dev.py test-mic --input-device 0`。

macOS 若弹出权限框，允许启动终端/Codex/Python 使用麦克风；拒绝后到系统设置「隐私与安全性 → 麦克风」检查。Windows 检查麦克风隐私权限及中文系统语音；缺少中文音色会返回明确错误。输出暂跟随系统默认扬声器。

macOS 的 `devices` 还会显示系统输出静音/音量。系统静音或音量为 0 时，播报返回明确错误，服务不会擅自修改系统设置。`test-mic` 超时会显示已采集采样数和峰值，帮助区分静音输入与识别问题。

`test-mic` 会显示检测到说话、临时转写和最终文字；仍先加载 ASR 模型，最多等待 15 秒。非零峰值不等于人声，VAD 阳性也不保证转写准确。独立电平仪、噪声误报率和不同设备效果仍需实测。系统输出静音不阻塞语音→文字。

## 游戏输入联调（A1）

1. 更新并安装后重启游戏加载最新 Mod；无需手动启动 Python。首次 QQ 会在后台加载识别模型，准备时也能 QQ 取消，未就绪前不打开麦克风。独立手动调试的服务会被复用，游戏不会替换或结束不属于它的进程。
2. 点击左上角「AI 搭子」旁的圆形麦克风图标，或 QQ / 点「开始语音」。图标开启不展开聊天面板；QQ 和「开始语音」会打开聊天页。文字模式默认自动切到语音→语音；输入专项应事先在设置中选择语音→文字；连接准备时图标为橙色，收到持续监听状态后变绿，灰色斜杠表示关闭，红色表示暂不可用。颜色表示服务/收音状态，不代表实时 VAD 或正在发声。
3. 开口后聊天输入框上方显示「正在听」和临时转写。短停顿可接着说；约 0.9 秒持续非人声后完成本句，解码还有额外耗时。每句最终文字只进入聊天一次；随后可以继续说，无需按键或唤醒。连续长句约 20 秒分段，避免一直等不到句尾。
4. AI 正在生成时，你补充的第一份有效临时转写会取消旧回复。补充说完后，把原问题和新内容合并成一次请求，读取最新可读游戏状态；界面只新增补充的话。取消期间最多暂存 4 句，过多时明确提示未接收。没有有效转写的短噪声不触发模型请求；已取消旧回复但补充最终为空时，恢复原问题。关闭或断线会清空这份上下文。
5. 再点击麦克风图标、按 QQ，或点「关闭语音」/窗口「关闭」，停止采集、取消未完成识别并清空未提交的语音。图标恢复灰色斜杠，回到文字模式；已提交的问题仍可完成文字回复。关闭后再说话不应进入游戏。

**开关行为：** 输入框打字、长按 Q、Ctrl/Cmd/Alt/Shift 组合键及窗口失焦时不触发 QQ。F9 只隐藏窗口，监听继续，常驻麦克风图标仍可点击关闭。每次重启游戏都回到文字模式和灰色关闭图标，不恢复语音输入或播报；旧配置中的开启标记也会忽略，新保存的窗口配置不再记录开启状态。连接期间同样可以点击图标或 QQ 关闭，关闭后不会自动恢复；保持开启时断线重连会恢复持续模式，但不重放旧句。

**进程管理：** QQ 关闭聊天时断开会话并停止采集，保留后台模型以加快下次开启；退出游戏时关闭私有标准输入管道，托管服务收到 EOF 后清理音频并退出，正常退出另有超时回收。同一游戏只启动一个自有服务；自有进程崩溃时自动重启，每次开启最多尝试启动 3 次，再次 QQ 开关可重新尝试。麦克风权限或缺少语音组件时在游戏内提示；文字聊天可继续。旧的手动服务若版本不兼容，需开发者结束或更新，游戏不会杀掉它。

做输入专项时先选择语音→文字，不点「试听」，不修改系统音量。当前基础输出使用半双工：播报时临时暂停识别，结束后恢复；QQ 此时也是关闭整个语音聊天，不是单句打断键。独立 `test-mic` 仍是最多 15 秒的一句识别诊断，游戏中的持续模式静默时不会因此关闭。

服务可先于游戏启动；没有有效会话文件时拒绝鉴权，绝不回退为接受任意令牌。游戏开启语音后写入随机会话信息，服务每次握手重新读取。默认位置：

- macOS：`~/Library/Application Support/SlayTheSpire2/spire-companion/voice-session.json`
- Windows：`%APPDATA%\SlayTheSpire2\spire-companion\voice-session.json`

自定义游戏用户目录可传 `--token-file "实际路径/voice-session.json"`。服务只绑定 `127.0.0.1:17860`，一次只接一个游戏实例。默认不保存录音或识别文本日志；游戏聊天与现有游戏日志仍可包含文字。

## 当前边界

- 持续模式已有 WebRTC VAD、临时转写和句尾收束；图标只显示连接状态，人声/转写反馈在聊天输入框上方。真实噪声误报、切句延迟和 Windows 麦克风仍需验收。
- **当前 QQ 使用免唤醒词的持续模式。** 旧 wake 模式仍兼容 ASR 文本开头匹配「搭子」，不等于专用唤醒模型；其准确率单独验收。
- 基础播报期间暂停识别并丢弃回声音频；QQ 关闭语音聊天。播报期间语音唤醒、真正的回声消除尚未实现。
- 自动播报当前覆盖成功聊天回复；主动发言、自动决策、低血提醒和安慰的播报挂点留待后续接入。
- 支持普通 FIFO、紧急插播、按条/组取消、清空、TTL、输入回执、重连与去重。断线后停止音频，不重放旧口令或旧播报。
- 音量/语速/音色选择、运行中切换设备、自定义唤醒词尚未实现；已接入自动启动与安装包纳入入口，Windows 独立运行时及完整安装仍待交付与实测；不支持的方法返回明确错误。
- 当前 AI 接收转写文字，未接收原始音频；转写质量、切句、回复相关性与 Windows 音频分别验收。此前无有效文本的测试超时不再代表最新输入状态。

## 自动检查与模拟服务

```bash
python3 scripts/game_dev.py check
python3 scripts/voice_dev.py check
```

跨语言检查使用本机 .NET 9，先构建游戏检查程序后运行：

```bash
SPIRE_VOICE_WIRE_CHECK=1 python3 scripts/voice_dev.py check
```

PowerShell：先执行 `$env:SPIRE_VOICE_WIRE_CHECK='1'`，再运行检查。CI 在 Windows/Linux 自动运行协议与 C# 客户端检查；这些检查不访问麦克风，不代替音频实测。

只调协议时使用 `voice/.venv/bin/python voice/mock_voice_server.py`（Windows：`voice\.venv\Scripts\python.exe voice\mock_voice_server.py`）。终端输入模拟 `input.final`，播报只打印文字，没有真实声音；真实服务和 mock 不可占用同一端口。

完整目标见[语音模块 API](../docs/语音模块-开发功能与API.md)，消息示例见[protocol](../protocol/README.md)。

语音组下一轮工作包、逐步测试命令、真人用例与报告格式统一见[语音组任务与测试清单（2026-11-09）](../docs/语音模块-接口与参数分析.md)，不把所有专项测试重新转交负责人。

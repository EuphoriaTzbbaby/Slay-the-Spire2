# 语音模块开发功能与 API（初稿）

## 1. 范围与职责

游戏端使用 C#，语音端使用 Python 独立进程，通过本机 WebSocket 交换 JSON 消息。本文是待实现的接口契约，不代表当前已有这些接口。

语音端负责音频采集、唤醒、语音识别、固定口令匹配、语音合成和播放。游戏端负责大模型对话、游戏决策、动作执行与权限检查。语音端不直接操作游戏。

第一版只支持中文，优先免费、本地运行；预留语言和唤醒词配置字段。默认唤醒词为“搭子”，后续支持玩家自行调整；自定义词语需要经过模型支持检查和识别效果验证，不承诺任意词语均可直接使用。

语音模块优先支持 Windows，首先完成 Windows 上的开发、打包和验收，再进行 macOS 适配。通信协议保持跨平台，音频设备、麦克风权限和模型依赖分别适配。此优先级仅针对语音模块，游戏模块的平台规划单独管理。

## 2. 已确认的交互规则

- 持续监听唤醒词，一次唤醒接收一句话，识别结束后回到等待唤醒。
- 播报期间仍检测唤醒词；唤醒后停止播报并接收新指令。
- 界面的打断按钮停止播报并开始收音；纯停止播放使用独立的停止命令。
- 支持“暂停”“恢复”“到你了”及少量固定说法，其他文本交给游戏端理解。
- 普通播报按顺序播放，紧急消息可以插播，支持取消过期消息。
- 玩家可以调整播报音量、语速，选择已安装且兼容的音色。
- 关闭麦克风后不采集、不识别唤醒词；静音播报不影响麦克风，两者独立控制。

## 3. 需要开发的功能

| 模块 | 开发内容 |
| --- | --- |
| 服务管理 | 模型加载、连接鉴权、就绪通知、心跳、状态查询、退出和资源释放。 |
| 音频设备 | 枚举和选择输入输出设备、处理权限拒绝和设备断开。 |
| 唤醒 | 中文唤醒词检测、重复触发抑制、播报期间唤醒、关闭监听。 |
| 语音识别 | 收音、语音活动检测、句末判断、最终文本、超时和识别失败处理。 |
| 口令匹配 | 固定说法映射为控制请求；一次发言只产生一次最终输入事件。 |
| 语音合成 | 中文文本转语音、选择可用音色、音量与语速设置。 |
| 播放调度 | 普通队列、紧急插播、有效期、按标识取消及清空队列。 |
| 打断 | 停止当前播放，取消当前发言关联的过期播报，并切换到收音。 |
| 回声与误触发控制 | 防止搭子自己的声音触发口令或唤醒，测试扬声器外放场景。 |
| 日志 | 记录请求、耗时、状态与错误；默认不保存原始录音。 |

## 4. 连接与消息格式

建议 Python 作为 WebSocket 服务端，仅绑定 `127.0.0.1`；由启动方传入端口和随机会话令牌，C# 作为客户端。握手完成前不得启动音频操作，令牌不写日志。

请求示例：

```json
{
  "version": 1,
  "kind": "request",
  "id": "req-001",
  "method": "speech.enqueue",
  "params": {
    "utterance_id": "utt-001",
    "text": "我先处理右边，打完交给你。",
    "priority": "normal",
    "ttl_ms": 10000
  }
}
```

响应使用相同 `id`，包含 `ok`，成功时包含 `result`，失败时包含 `error: {code, message, retryable}`。入队成功只表示请求已接受，播放完成以事件为准。

事件示例：

```json
{
  "version": 1,
  "kind": "event",
  "event_id": "evt-001",
  "session_id": "voice-session-001",
  "seq": 12,
  "name": "input.final",
  "data": {
    "input_id": "input-001",
    "text": "到你了",
    "language": "zh-CN",
    "intent": "handoff"
  }
}
```

每个连接会话的事件序号递增。相同请求 ID 不得重复触发副作用；游戏端按会话和输入 ID 去重。重连后不自动重放旧控制指令或旧播报，先查询状态。

## 5. C# → Python 请求 API

| 方法 | 主要参数 | 作用 |
| --- | --- | --- |
| `session.hello` | `token`, `protocol_version` | 鉴权与协议协商，返回会话 ID、功能清单和加载状态。 |
| `service.status` | 无 | 获取模型就绪状态、收音状态、播放状态、当前播报和队列长度。 |
| `service.ping` | 无 | 检查连接活性。 |
| `devices.list` | 无 | 获取输入输出设备及当前默认设备。 |
| `devices.select` | `input_device_id`, `output_device_id` | 选择设备；失败时报告错误并保留可用状态。 |
| `listening.start` | 无 | 开启采集并等待唤醒；模型未就绪则拒绝。 |
| `listening.stop` | 无 | 停止采集并取消正在进行的识别，不发送残留口令。 |
| `recognition.cancel` | `input_id` | 取消本次收音，返回等待唤醒。 |
| `speech.enqueue` | `utterance_id`, `text`, `priority`, `ttl_ms`, 可选 `group_id` | 提交播报，优先级为 `normal` 或 `urgent`。 |
| `speech.cancel` | `utterance_id` 或 `group_id` | 取消指定的排队或正在播放内容。 |
| `speech.clear` | `include_current` | 清空队列，可同时停止当前播放，不自动开始收音。 |
| `speech.interrupt` | 可选 `group_id` | 停止当前播报并开始收音；麦克风关闭时返回明确错误，不擅自开启。 |
| `settings.get` | 无 | 返回当前设置、可用音色和支持的配置范围。 |
| `settings.update` | 部分设置字段 | 校验并更新音量、语速、音色、播报静音等设置。 |
| `service.shutdown` | 无 | 停止音频任务、释放设备并退出。 |

`wake_word` 默认值为“搭子”，第一版先使用该默认词，后续通过配置接口支持玩家调整；未支持的词语返回明确错误并保留原设置。`language` 第一版只接受 `zh-CN`。音量、语速和音色允许通过 `settings.update` 调整，可用范围与已安装音色通过 `settings.get` 查询。

## 6. Python → C# 事件 API

| 事件 | 主要内容 | 用途 |
| --- | --- | --- |
| `service.ready` | 可用能力、模型信息 | 模型和音频组件准备完成。 |
| `state.changed` | 当前收音与播放状态 | 更新监听、识别、播放等界面提示。 |
| `wake.detected` | `input_id`, 唤醒词 | 通知检测到唤醒；一次唤醒只创建一个输入 ID。 |
| `recognition.started` | `input_id` | 开始接收玩家发言。 |
| `input.final` | `input_id`, `text`, `language`, `intent` | 唯一的最终输入事件；普通文本的 `intent` 为 `null`。 |
| `recognition.timeout` | `input_id`, 原因 | 未收到有效语音或达到时限，不执行游戏指令。 |
| `recognition.cancelled` | `input_id`, 原因 | 本次输入取消。 |
| `speech.started` | `utterance_id` | 实际开始播放。 |
| `speech.completed` | `utterance_id` | 播放完成。 |
| `speech.cancelled` | `utterance_id`, 原因 | 因取消、插播、过期、静音或打断而终止。 |
| `service.error` | 错误码、说明、是否可重试、关联 ID | 通知异步模型或设备错误。 |

每次识别只产生一个终态：最终输入、超时、取消或错误。每条接受的播报也必须有且只有一个完成、取消或失败终态。

## 7. 控制口令与执行回执

| 固定说法示例 | `intent` | 游戏端职责 |
| --- | --- | --- |
| 暂停、等一下 | `pause` | 停止提交 AI 新动作。 |
| 恢复、继续操作 | `resume` | 检查状态后恢复托管。 |
| 到你了、你来打 | `handoff` | 当前允许交接时启动 AI 行动。 |

只对完整匹配或受控归一化后的固定说法映射口令；“先别暂停”等混合语句不按关键词命中。其他表达以普通文本发送给游戏端。

`input.final` 同时携带原文和可选意图，避免分别发送文本与指令造成重复执行。识别出固定意图后，游戏端不再把同一输入作为普通对话重复处理。

增加游戏端请求 `input.ack`：参数为 `input_id`、`status`（`accepted`、`rejected` 或 `ignored`）和可选原因，用于确认已收到并处理。语音识别成功不等于游戏动作执行成功，最终执行结果由游戏端负责展示和反馈。

## 8. 状态与播报规则

收音状态与播放状态分别维护，避免“正在播放”和“等待唤醒”无法同时表达：

- 收音：`disabled`、`waiting_wake`、`listening`、`recognizing`。
- 播放：`idle`、`synthesizing`、`playing`。
- 服务：`loading`、`ready`、`error`、`stopping`。

普通消息先进先出；紧急消息打断当前播报，当前被打断内容取消，不自动从头重播，其他未过期队列保留。玩家唤醒打断时清除当时已有的播报队列，避免识别后继续播放旧回复。

`ttl_ms` 从接受请求时计时，合成前和播放前均检查；已经开始的播报超时也应取消。游戏端通过 `group_id` 取消已失效战局或对话关联的消息。

断开游戏端连接时，停止收音和播放、清空队列；重连后由游戏端明确恢复监听。模型加载、音频采集和合成工作不得阻塞连接的心跳与取消处理。

## 9. 错误与验收

至少区分：鉴权失败、协议不兼容、模型未就绪、模型加载失败、麦克风权限拒绝、设备不可用、不支持配置、识别失败和合成失败。取消与普通超时不作为服务崩溃处理。

验收重点：

- 一次唤醒只形成一次有效输入，结束后重新等待唤醒。
- 唤醒打断和按钮打断均能停止播报并进入收音。
- 固定口令无需调用大模型，重复消息不会重复操作游戏。
- 普通队列、紧急插播、过期取消和分组取消符合约定。
- 麦克风关闭时不采集，播报静音时不播放。
- 权限拒绝、设备断开和服务重连均有清晰反馈。
- 双开游戏与本地语音同时运行时，测试识别率、响应耗时、CPU、内存和游戏流畅度。
- 优先在 Windows 验证模型安装与加载、麦克风权限、设备选择、打包启动和完整语音流程；macOS 后续单独验收。
- 外放时不会因 AI 自己的声音反复唤醒或形成反馈循环。

## 10. 待确认参数

- 无语音等待、句末静音判定和单句最长时限。
- 默认音色、语速和音量的具体值；已确定允许玩家调整音量、语速并选择已安装音色。
- 目标 Windows 电脑的 CPU、内存及可接受的识别、打断和播报延迟；macOS 适配阶段另行确认目标硬件。
- 启动、打包和安装方式；第一版不要求玩家自行安装 Python。

# 语音模块：要做的事与游戏端输出参数（分析）

日期：2026-10-28  
依据：[语音模块开发功能与 API](语音模块-开发功能与API.md)、[协议目录](../protocol/README.md)、[语音与游戏模块拆解](13-语音与游戏模块拆解.md)。  
结论先说：**协议已经定好，代码一行没写**。游戏端目前没有 WebSocket 客户端，语音端只有 `voice/README.md`。

---

## 1. 边界：谁负责什么

```text
麦克风 → 语音端（唤醒/ASR/口令） → input.final → 游戏端（理解/决策/执行）
                                    ↑
游戏端（生成要说的文本/优先级） → speech.enqueue → 语音端（清洗/TTS/队列/播放）
```

- **游戏端**：决定"说什么"（内容、优先级、有效期、分组），不碰音频。
- **语音端**：决定"怎么说、什么时候说"（清洗、口语化、TTS、队列、打断、回声控制），不碰游戏。
- 固定口令（暂停/恢复/到你了）在语音端匹配，游戏端只执行，避免再绕一次大模型。

## 2. 语音端要做的工作包

| 编号 | 工作包 | 具体内容 | 建议 owner |
| --- | --- | --- | --- |
| W1 | 服务与协议 | 本机 WebSocket 服务、`session.hello` 鉴权、心跳、重连、状态机、`service.shutdown` | 胡 |
| W2 | 音频设备 | 枚举/选择输入输出、权限拒绝、设备断开、默认设备回退 | 胡 |
| W3 | 唤醒 | 中文唤醒词「搭子」、重复触发抑制、播报期间也能唤醒、关闭监听 | 马/胡 |
| W4 | 识别 | 收音、VAD、句末判定、超时、最终文本、失败处理、一次唤醒只出一个 `input.final` | 胡 |
| W5 | 口令与意图 | 「暂停/恢复/到你了」等固定说法归一化；混合语句不按关键词误命中 | 马 |
| W6 | 文本清洗与口语化 | 去 Markdown/BBCode/动作 ID/表格/URL；长句切短；不伪造数值 | 马 |
| W7 | TTS | `SpeechProvider` 接口；系统 TTS（Windows SAPI / macOS say）与云端 TTS；音色、语速、音量 | 胡 |
| W8 | 播放调度 | 普通队列 FIFO、紧急插播、`ttl_ms` 过期、`group_id` 取消、清空 | 胡 |
| W9 | 打断与回声 | 唤醒/按钮打断立即停播并收音；播放时不被自己的声音再次唤醒 | 胡/马 |
| W10 | 设置与日志 | 音量/语速/音色/仅字幕；开关持久化；不保存原始录音 | 付/胡 |
| W11 | 打包 | Windows 优先：不要求玩家装 Python；模型随包或首次下载 | 胡 |
| W12 | 验收 | 延迟（首包 <2s 目标）、识别率、CPU/内存、双开、外放反馈循环 | 共同 |

## 3. 游戏端要输出的参数

### 3.1 握手

`session.hello`：

| 参数 | 说明 |
| --- | --- |
| `token` | 启动方传入的随机令牌，只走本机回环，不写日志 |
| `protocol_version` | 当前 `1` |

### 3.2 播报请求 `speech.enqueue`（核心）

现有协议字段 + 建议扩展（**扩展需双方评审**）：

| 字段 | 类型 | 必填 | 说明 | 示例 |
| --- | --- | --- | --- | --- |
| `utterance_id` | string | 是 | 全局唯一；重复 ID 不得重复播报 | `utt-000123` |
| `text` | string | 是 | **纯文本**（无 Markdown/BBCode/动作 ID） | `我选了祭品，零费过三张。` |
| `priority` | `normal`/`urgent` | 是 | 紧急插播会打断当前句 | `normal` |
| `ttl_ms` | int | 是 | 从接受时计时；合成前、播放前都检查 | `8000` |
| `group_id` | string | 否 | 同一战局/同一对话分组，便于整组取消 | `room-20772828` |
| `category`（建议） | string | 否 | `decision`/`advice`/`proactive`/`warning`/`comfort`，供语音策略与统计 | `decision` |
| `scene`（建议） | string | 否 | 生成时场景，便于日志定位 | `CombatRoom` |
| `dedupe_key`（建议） | string | 否 | 相同内容合并，避免重复播报 | `select:14:祭品` |

游戏端应保证：**同一条内容只入队一次**；文本里不出现 `c1@enemy`、`**加粗**`、表格、URL。

### 3.3 建议的优先级与有效期

| 游戏事件 | category | priority | ttl_ms | group_id |
| --- | --- | --- | --- | --- |
| 自动决策理由（"我选了…"） | decision | normal | 8000 | 当前房间 ID |
| 主动发言（战斗开场） | proactive | normal | 6000 | 当前战斗 ID |
| 低血提醒 | warning | urgent | 15000 | 当前战斗 ID |
| 失败安慰 | comfort | normal | 30000 | 当前跑局 ID |
| 玩家提问的回答 | advice | normal | 30000 | 对话 ID |
| "已暂停/已恢复"回执 | decision | urgent | 5000 | 控制 ID |

场景切换（离开房间、战斗结束）时，游戏端用 `speech.cancel` 按 `group_id` 取消旧内容，避免"人已经走了还在说上一屏"。

### 3.4 取消与打断

| 方法 | 何时调用 |
| --- | --- |
| `speech.cancel(utterance_id/group_id)` | 决策过期、场景切换、玩家打断 |
| `speech.clear(include_current)` | 清空队列（如退出游戏、切档案） |
| `speech.interrupt` | 玩家唤醒打断播报（语音端内部也会处理） |

### 3.5 设置与状态

- `settings.get/update`：音量、语速、音色、播报静音、唤醒词（第一版固定「搭子」）。
- `service.status`：模型是否就绪、收音状态、播放状态、队列长度。
- `service.ping`：健康检查。

### 3.6 输入回执 `input.ack`（游戏端 → 语音端）

| 参数 | 说明 |
| --- | --- |
| `input_id` | 对应 `input.final` |
| `status` | `accepted` / `rejected` / `ignored` |
| `reason` | 可选，如"当前不能暂停" |

用途：语音端知道游戏端确实处理了，不会因为没回执而重试导致重复执行。

## 4. 语音端要发给游戏端的事件

| 事件 | 关键字段 | 游戏端怎么用 |
| --- | --- | --- |
| `wake.detected` | `input_id` | UI 显示"在听"；可暂停播报 |
| `recognition.started` | `input_id` | UI 显示"识别中" |
| `input.final` | `input_id`, `text`, `language`, `intent` | `intent` 为空 → 当聊天问题；`pause`/`resume`/`handoff` → 直接执行控制 |
| `recognition.timeout` | `input_id`, 原因 | 提示"没听清"，不执行任何动作 |
| `recognition.cancelled` | `input_id`, 原因 | 清理 UI |
| `speech.started/completed/cancelled` | `utterance_id` | 更新"正在说/说完了"，据此释放队列状态 |
| `state.changed` | 收音/播放状态 | 面板显示麦克风与播放图标 |
| `service.error` | 错误码、可重试 | 聊天里提示，不阻塞游戏 |

去重规则：**按 `input_id` 去重**；重连后不重放旧指令，先 `service.status` 再恢复监听。

## 5. 两个典型时序

### 5.1 玩家语音提问

```text
玩家："搭子，这手牌怎么打？"
→ wake.detected → recognition.started → input.final(intent=null)
→ 游戏端：input.ack(accepted) → 生成回答 → speech.enqueue(advice, ttl=30s)
→ 语音端：清洗 → TTS → 播放 → speech.completed
```

### 5.2 自动决策播报

```text
自动模式选中「祭品」
→ 游戏端生成文本"我选了祭品，零费过三张。" → speech.enqueue(decision, normal, 8s, group=room)
→ 若 8 秒内场景切换：speech.cancel(group=room)，不再播
→ 否则语音端播放；玩家说"暂停" → input.final(intent=pause) → 游戏端暂停自动 → speech.enqueue("已暂停", urgent)
```

## 6. 游戏端还缺的实现（P5 剩余）

| 任务 | 说明 |
| --- | --- |
| WebSocket 客户端 | 目前没有；需要连接 `127.0.0.1`、握手、重连、心跳 |
| 播报挂点 | 自动决策、主动发言、安慰、语音提问的回答，统一走 `speech.enqueue` |
| 文本清洗 | 发送前去掉 Markdown/BBCode/动作 ID（也可交给语音端，但游戏端要保证不乱码） |
| 场景切换取消 | 按 `group_id` 取消过期播报 |
| 输入路由 | `input.final` 的 intent 执行、普通文本走聊天、`input.ack` 回执、按 `input_id` 去重 |
| UI 状态 | 麦克风开/关、在听/识别中/播报中、语音打断按钮 |
| 语音打断与自动挂起 | 复用现有 `SuspendAuto`：语音打断 → 暂停自动 → 讨论后再恢复 |

# 《杀戮尖塔 2》AI 双排陪玩简版需求分析

## 1. 产品目标与范围

玩家与 AI 各控制一个角色，在同一局中合作爬塔。AI 能自主操作自己的角色、理解双方局势、提出配合建议，并通过自然、有趣的文字和语音交流提供陪玩体验。

- 保留单人托管和双人陪玩两种模式；本文仅描述双人陪玩。
- 第一版双方角色均限定为铁甲战士。
- 同一台电脑运行两个游戏实例，联机加入同一队伍；玩家操作自己的实例，AI 操作另一个实例。
- 支持 macOS 和 Windows，优先在 macOS 开发与验收。同机双开和后台运行的实际可行性需要验证。
- 聊天、局外策略和战斗协作判断可以调用在线大模型。
- 语音优先采用免费、本地运行的方案。

## 2. 控制权限与信息范围

| 项目 | 要求 |
| --- | --- |
| 玩家角色 | 玩家自行决定和执行出牌，AI 不代替玩家操作。 |
| AI 角色 | AI 自主出牌、选牌、购物和用药，重要决定简短告知玩家。 |
| 团队关键选择 | 路线及团队关键选择由 AI 提建议、玩家拍板；玩家未回应时等待。 |
| 信息读取 | 可读取双方手牌和公开战斗状态，不读取隐藏抽牌顺序。 |
| 玩家建议 | 玩家主动询问时，AI 提供选牌、购物、路线和出牌建议，由玩家操作。 |
| 暂停与接管 | 玩家随时暂停 AI 或手动接管 AI 角色，恢复后重新读取状态。 |

## 3. 功能需求

| 模块 | 第一版要求 |
| --- | --- |
| 双开与组队 | 启动或连接第二游戏实例，加入同一队伍，绑定 AI 角色，并隔离实例配置和存档。 |
| 双方状态感知 | 区分双方身份，获取双方手牌、血量、状态、资源、行动状态和共同战局。 |
| 局外个人决策 | AI 根据自己的卡组与团队需求，自主选择卡牌、遗物、商店商品、删牌及药水管理方案。 |
| 团队协商 | 对路线、开局祝福和每幕特殊选择等场景，区分个人与共同决策；团队关键选择等待玩家决定。 |
| 战斗协作 | 根据当前局势判断先后手，配合集火、辅助、目标选择和资源使用，优先保证流畅。 |
| 战术交流 | 理解“等一下”“到你了”“集火右边”等指令；可以主动建议配合，但不强制限制玩家操作。 |
| 战斗求解 | 使用适配多人战斗的 CombatSolver，仅计算和执行 AI 角色的动作。 |
| 联机同步 | 执行前检查最新状态、行动权限和目标，避免重复操作与过期方案执行。 |
| 异常处理 | 处理断线、实例退出、状态不同步等情况，暂停操作并明确提示，不盲目重放动作。 |
| 文字与语音 | 支持聊天、持续监听与唤醒词输入、语音播报、打断、静音及麦克风关闭。 |
| 陪玩性格 | 幽默朋友型，适当接梗、安慰，支持安静、普通、话多三种模式。 |

## 4. 战斗协作流程

1. 每回合开始，AI 根据双方手牌和公开战局判断谁先行动，并简短说明必要的配合。
2. 如果 AI 先打，直接开始自己的行动；如果玩家先打，等待玩家交接。
3. 玩家说“到你了”、点击交接按钮，或结束自己的回合，均视为交接。
4. 交接后读取最新状态，由 CombatSolver 计算并执行 AI 的一组动作。
5. AI 打完一组动作后明确告知“到你了”，等待玩家再次交接；若已经没有后续动作，则自主结束自己的回合并告知玩家。
6. 玩家可以不接受配合建议。AI 根据实际发生的动作调整，不将建议当作玩家已经执行的操作。

AI 不预测玩家尚未打出的牌并将其作为确定结果。玩家已经完成的动作纳入当前状态，求解以交接时的最新局面为依据。

## 5. CombatSolver 多人适配要求

### 求解目标

只搜索 AI 自己的动作，优先避免任何一方死亡，在能够获胜的前提下尽量减少双方总受伤。药水优先保留，但 AI 可在保命、避免大量战损或提高获胜机会时自主使用。

玩家未来的操作属于不确定因素。求解结果必须说明适用范围，不能将当前局部方案表述为已验证的整场获胜路线，也不承诺团队全局最优。

### 状态与执行

- 正确模拟多人敌人机制、攻击目标、双方状态及队友产生的效果。
- 玩家出牌或局势变化后，校验 AI 剩余方案的前提、目标和效果；仍适用的动作继续执行，必要时重算。
- 动作合法不等于原方案仍然有效，不能只检查“这张牌还能不能打”。
- AI 不操作玩家角色，不搜索玩家的出牌序列，不读取隐藏抽牌顺序。

### 搜索预算与失败处理

- 沿用限时求解方向：争取几秒内提供可行方案，继续优化，并允许设置最长等待时间。
- 超时后尚未找到获胜路线时，根据搜索进展选择延长计算，或执行较好的局部方案后重新求解，明确说明不确定性。
- 多人适配未完成、求解失败或遇到不支持机制时，暂停 AI 操作，提示原因并允许玩家手动接管；不自动切换为大模型出牌。
- 普通搜索超时与不支持、异常失败需要明确区分。

本地 CombatSolver 当前文档以单人战斗为支持范围。即使只控制 AI 一个角色，也必须完成多人模拟和执行适配，不能直接视作现成可用能力。

## 6. 技术复用方向

| 项目或组件 | 复用方向 | 需要补充或验证 |
| --- | --- | --- |
| STS2-Agent | 本地双开、联机组队、队友身份与状态、动作接口和决策日志。 | macOS 双开路径、实例隔离、恢复流程，以及本项目所需队友信息。 |
| Spire Buddy | 聊天、性格配置、局外决策、状态校验和停止机制。 | 双人角色归属、团队协商及战斗交接；与联机控制层的整合。 |
| CombatSolver | 搜索框架、预算控制、路线复用、药水评估和自动执行。 | 多人战斗模拟、团队战损评价、仅 AI 行动搜索，以及队友操作后的方案校验。 |
| 在线大模型 | 局外策略、先后手判断、协作建议和自然语言解释。 | 结构化输出、响应速度及建议与实际动作的一致性。 |
| 本地语音组件 | 唤醒、识别和播报。 | 需要新增，验证双开时的识别效果和资源占用。 |

以上为复用方向，最终主程序与模块整合方式需通过技术验证确定，避免多个控制器同时提交游戏动作。

## 7. 验收重点

| 验收项 | 要求 |
| --- | --- |
| 双开组队 | 两个实例加入同一局，双方角色身份正确，配置和存档不互相覆盖。 |
| 控制隔离 | AI 仅操作自己的角色，玩家始终能够独立操作。 |
| 交接流程 | 口令、按钮和玩家结束回合均能触发交接，避免重复触发。 |
| 团队协商 | 关键选择等待玩家拍板，未回应时不擅自决定。 |
| 战斗协作 | 配合建议基于当前状态，不依赖玩家执行尚未确认的动作。 |
| 多人求解 | 代表场景中模拟与实际效果一致，正确识别团队战损和不支持边界。 |
| 方案更新 | 玩家改变战局后，正确继续有效动作或重算，不执行过期方案。 |
| 暂停与异常 | 停止提交新动作；求解失败时明确提示并支持手动接管。 |
| 陪玩体验 | 交流自然，发言模式有区别，语音交接与打断可用。 |
| 性能与平台 | 分别验证 macOS 和 Windows；在双开、语音和搜索同时运行时评估响应、内存占用与流畅度。 |

## 8. 待确定与待验证事项

- 目标 Mac 的芯片、内存和可接受的双开资源占用。
- 默认搜索等待时间、自动延长次数或累计时间上限。
- CombatSolver 多人适配的可行性、工作量和团队战损评价方式。
- 双方手牌读取、多人结束回合及角色行动权限的实际接口。
- macOS 双开组队、后台窗口运行和手动接管方式。
- 断线恢复策略及本地语音组件选型。

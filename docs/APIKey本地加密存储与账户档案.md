# API Key 本地加密存储与账户档案

## 已确认的方案

- 第一阶段采用 macOS 与 Windows 共用格式的本地加密文件。
- 每位玩家先创建自己的本地档案，并使用自己的 API Key。
- 档案有解锁密码；允许本机自动解锁，系统安全存储只保存随机的文件解密凭据。
- 用户已有云服务器，数据库类型为 MySQL。云端注册、登录和同步以后接入，本轮不连接或修改数据库。

本地档案用于区分配置，不等同于经过服务器认证的账号。自动解锁依赖当前操作系统用户的授权，同一个操作系统用户下的多个档案不构成严格的多人权限边界。

## 游戏窗口中的使用步骤

1. 重启游戏，在“聊天与 API”页签上方填写本地档案名和至少 8 字符的解锁密码，点击“创建本地档案”。
2. 按需勾选“在本机自动解锁”。勾选后，下次启动会尝试自动打开上次使用的档案。
3. 填写模型配置和 API Key，勾选“记住 API Key”，点击“保存设置”。
4. 切换玩家时，选择对应档案，点击“解锁 / 切换”；可以使用系统缓存，或输入该档案密码。
5. “锁定档案”清除内存中的当前凭据和对话，不删除加密文件或自动解锁缓存。
6. 不再希望自动解锁时，取消该选项并点击“解锁 / 切换”应用；系统删除失败会提示，不假装已清除。

没有解锁档案时仍可临时填写密钥进行会话聊天，但不能把它持久保存到档案。切换档案期间不能发送模型请求；模型请求期间需先取消并等待结束，再切换档案。

## 保存在哪里

路径均由 Godot 的 user:// 映射到对应系统用户数据目录：

```text
user://spire-companion/
├── last-profile.json                 # 上次档案标识、自动解锁偏好，无密钥或密码
├── chat-settings.json                # 旧会话/未选择档案时的非秘密配置
└── profiles/
    ├── <档案GUID>.vault.json         # 加密 API Key 数据及密码包装信息
    ├── <档案GUID>.settings.json      # 该档案的地址、模型和回复风格等
    └── *.lock                       # 写入互斥文件，不含秘密
```

API Key 不直接保存在系统钥匙串或普通配置中，也不进入 Git。macOS 钥匙串与 Windows 凭据管理器仅缓存随机数据密钥，档案密码不写入文件或系统缓存。

## 跨平台格式与加密方式

- 每个档案独立生成 256 位随机数据密钥。
- 使用 AES-256-GCM 加密 API Key 集合，采用随机 12 字节 nonce 和 16 字节认证标签。
- 档案密码通过 PBKDF2-SHA256、随机 16 字节盐与 600,000 次迭代派生包装密钥；包装密钥加密随机数据密钥。
- 档案 ID、名字、格式版本和用途参与认证上下文，错误档案或篡改数据不能静默解密。
- 同一档案按服务地址来源区分密钥，删除一个服务不会删除其他服务或其他档案的数据。
- 临时文件写入完成并刷新后原子替换；写入有互斥检查，不在密码错误或格式未知时覆盖原文件。
- 锁定时清除会话的数据密钥字节。解锁密码、API Key 等托管字符串仍受到进程内存生命周期限制，不承诺从物理内存完全擦除。

加密格式相同，因此复制档案文件到另一系统后可以使用档案密码解锁；自动解锁缓存属于设备，不随文件复制。完整导入导出界面和跨设备 UI 验收尚未实现。

参考：[.NET AesGcm](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.aesgcm)、[.NET PBKDF2](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.rfc2898derivebytes.pbkdf2)。

## 旧数据迁移

窗口提供“导入此前保存的系统密钥（可选）”。先解锁目标档案，再点击导入，旧密钥会加密写入该档案。不会擅自删除以前的系统密钥，也不会自动把同一旧密钥分发给所有档案。

旧设置中的非空地址与模型保持原样；新档案默认 https://api.deepseek.com 和 deepseek-flash。

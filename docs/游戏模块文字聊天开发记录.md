# 在线模型与文字聊天开发记录

日期：2026-10-27。范围：只读对话、当前状态分析、配置与取消。不包含局外自动决策执行，也没有启动游戏验收或调用付费模型。

## 已实现

- C# 核心使用 HTTP Chat Completions 协议；支持填写基础地址（如 https://服务地址/v1）或完整 /chat/completions 地址。
- 支持配置模型名、会话 API Key、安静/普通/话多的回复风格。
- “发送”和“分析当前局面”共用客户端，发送玩家提问与提问时的状态快照。
- 最多保留最近 6 轮对话，并限制历史总长度；当前状态始终来自本轮快照。
- 生成建议与游戏动作完全分离；回复文本不能触发出牌、购物或用药。
- 请求超时、取消、空回复、无效 JSON、服务错误和超大响应有明确提示。
- 同一会话一次只允许一条请求，避免重复发送；取消不写入会话历史。
- 网络处理在后台，Godot 控件更新通过主线程队列处理。
- 取消和暂停会使已排队的旧回复失效；退出时取消请求。
- 回复返回后复核状态指纹，变化时明确标注“基于提问时的状态”。
- 配置保存地址、模型、回复风格和超时参数；密钥仅保存在本次运行内存，也可从 SPIRE_COMPANION_API_KEY 环境变量读取。
- 聊天控件加入可滚动开发面板，避免配置和聊天记录把操作区全部挤出。

## 使用方式

重新启动游戏加载更新后，按 F9 打开面板，在文字搭子区填写：

1. 模型地址：服务商提供的 OpenAI-compatible Chat Completions 基础地址。
2. 模型名：该服务实际可用的模型名称。
3. API Key：服务需要时填写，只用于当前会话，不保存在配置文件，也不要发到 GitHub 或聊天记录。
4. 保存配置，再手动发送一句话或点击“分析当前局面”。

配置位于 user://spire-companion/chat-settings.json。对话历史不落盘。填写或保存配置不会发起模型请求，只有主动发送时才调用服务；实际费用由所选服务决定。

当前不支持 Responses 协议、流式显示、语音播报或模型工具调用。只提供 Responses 接口的服务暂时不能使用；不要把“OpenAI-compatible”理解为所有服务功能均兼容。

## 建议所依据的信息

当前可发送角色、血量、金币、能量、格挡、手牌、牌组、遗物、药水和敌人基础状态；局外界面已接入事件（标题/描述/选项/锁定）、卡牌奖励（候选与费用）、商店（商品/价格/售罄/买不起）、休息点（选项与可用性）、地图（当前点的可达子节点类型）。卡牌效果全文与敌人意图尚未接入，模型应说明信息不足，不得编造。

安静/普通/话多目前影响回复长度和语气；主动发言触发、去重和安慰时机仍需开发，不能将三个按钮选项视作完整陪玩体验已验收。

## 2026-10-27 更新：回复渲染、奶龙形象与导出反馈

- 回复原来放在只读 `TextEdit` 里，禁用了可编辑后使用游戏主题的 `font_readonly_color`，在奶油底上几乎看不见。改为 `RichTextLabel`，正文颜色由本项目主题控制。
- 模型回复是 Markdown，原来按纯文本原样显示（`**加粗**`、列表符号、代码反引号）。新增 `ChatMarkdown.ToBbcode`：加粗、斜体、标题、列表、行内代码、代码块和链接转成 BBCode；方括号统一转义，避免被当成 BBCode 标签执行。发送方（你/奶龙）用不同颜色标注。
- 新增 1 项独立检查覆盖 Markdown 转换与方括号转义，独立检查总数 27。
- 窗口加入奶龙头像（标题左侧、聊天欢迎区、入口按钮图标），素材来自团队答辩 PPT，已补充来源与非分发说明。
- 「导出当前状态」原来只提示“文件位置见日志”，现在把完整路径直接显示在面板上。

## 2026-10-27 更新：对话气泡与按钮层级

- 对话由单一文本区改为气泡列表：每条回复左侧带奶龙头像，用户消息用蜂蜜色气泡，助手回复用白色气泡，自动滚到底部，最多保留 60 条可见气泡。
- 空对话时显示奶龙欢迎语（头像 + 气泡），发送第一条消息后收起。
- 按钮按层级统一：主操作用橙色实心（发送、保存设置、手动结束回合），次要用白底橙框（分析局面、测试连接、暂停、接管），低强调用无底色（清空、取消、导出、锁定），删除密钥用浅红警示样式；高度统一为 40–46，最小宽度补齐。

- 新增 1 项独立检查：`Room` 选项变化必须改变快照指纹（总数 28）。

## 2026-10-27 更新：局外界面读取

| 界面 | 读取方式 | 字段 |
| --- | --- | --- |
| 事件 | `EventRoom.LocalMutableEvent`（回退 `CanonicalEvent`） | 标题、描述、选项、是否锁定 |
| 卡牌奖励 | 覆盖层 `NCardRewardSelectionScreen` 下的卡牌持有者 | 卡名、费用、是否已升级 |
| 商店 | `MerchantRoom.GetLocalInventory()` | 商品名、价格、售罄、是否买得起、打折、删牌服务 |
| 休息点 | `RestSiteRoom.Options` | 选项名、描述、是否可用 |
| 地图 | `RunState.CurrentMapPoint.Children` | 仅可达子节点及其房间类型，不推断未暴露拓扑 |

说明与限制：

- 卡牌奖励只能从界面节点读取（没有模型列表），卡片未渲染时可能读不到，此时返回空而不猜测。
- 地图只给当前节点的直接子节点，不给整张图，避免把未知房间当成已知。
- 商店刚进门时库存可能尚未生成，读不到就返回空，不伪造商品。
- 以上字段名来自游戏程序集反射，**尚未在真实界面逐项核对**，实机时以导出 JSON 为准。

## 2026-10-27 更新：空回复与按钮焦点

- 回复解析兼容 `content` 为字符串或分段数组（部分兼容服务按 parts 返回）。
- 正文为空时区分原因：只有 `reasoning_content` → 提示改用非推理模型或调大输出；`finish_reason=length` → 提示被截断；其余提示空正文。不再一律报“服务不支持 Chat Completions”。
- 面板按钮补 `font_focus_color`：之前按钮被点击后保持焦点，沿用游戏主题的浅色焦点字体，在浅色按钮上等于看不见。
- 手动操作改为有状态：启用后按钮文案变“手动操作已启用”并禁用；结束回合不再自动把模块切回暂停，避免每回合都要重新启用（过期动作仍由快照指纹拦截）。
- 独立检查增至 29 项。

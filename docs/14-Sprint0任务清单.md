## 1. Sprint 0 目标

> 做一个能跑、能看、能解释的观战搭子 MVP：

```text
读当前状态
  -> 战斗建议（动作/目标/掉血/击杀）
  -> 抓牌建议（top-1/top-3/skip + 理由）
  -> 面板展示
  -> 简单文字人格
```

**不包含：**

- 自动出牌
- 语音/TTS
- AI 第二角色
- 全角色/全卡池

## 2. 当前环境决策

现状：

- `127.0.0.1:15526` 的 STS2MCP 在运行；
- `127.0.0.1:8080` 的 STS2-Agent 未运行；
- 已有 SpirePilot 的 STS2MCP adapter、exact/beam/rollout、Tkinter overlay。

Sprint 0 决定：

> **A 先用 STS2MCP 作为状态源，接口抽象成 `StateSource`；STS2-Agent adapter 作为下一步接入。**

原因：

- 15526 现在可用，能马上开发/验证；
- STS2-Agent 的 8080 未启动，且 co-op/overlay 是 C 阶段的事；
- 用 interface 隔离，后面换源不改决策层。

```text
StateSource
  ├─ Sts2McpSource（Sprint 0）
  └─ Sts2AgentSource（Sprint 1+）
```

## 4. 7 天排期

### Day 1：状态源

- 抓 3 条状态：战斗、奖励、商店/地图
- 定义 `StateSource`：
  ```python
  class StateSource(Protocol):
      def fetch(self) -> dict: ...
      def state_type(self) -> str: ...
  ```
- STS2MCP source：复用 `sts2mcp.py`
- 错误处理：连接失败/非战斗/解析失败

**验收**：一条命令打印当前状态摘要。

### Day 2：战斗建议

- 复用 exact/beam
- 输出：
  - 动作 + 手牌索引 + 目标
  - 预计掉血/敌方 HP/击杀
  - 备选 top-3
- 接入 `live`/服务函数

**验收**：当前战斗建议与游戏内一致；非法动作 0。

### Day 3：抓牌评分

- 卡牌库 87 张 Ironclad
- 评分维度：
  - 基础强度/费用
  - 牌组协同（攻击/防御/抽牌/能力）
  - 当前 Act/HP
  - skip
- 输出 top-1 + 2–3 条理由

**验收**：三选一有排序；理由引用具体牌/数值；不幻觉。

### Day 4：面板 v0

- 现有 overlay 改造：
  - 手牌 `[0]…[4]`
  - 推荐 + 索引 + 目标
  - 预计掉血/敌方 HP
  - 备选/理由
- 失败显示错误，不崩

**验收**：一屏能看懂；延迟 < 2 s。

### Day 5：文字人格 v0

- 3 类场景：
  - 战斗开始/关键回合
  - 选牌/跳过
  - 玩家失误/危险
- 模板 + LLM 可选；不刷屏
- 不伪造数值

**验收**：像队友，不冒犯；可关闭。

### Day 6：测试与回归

- fixture：战斗/奖励/商店
- 单测：状态解析、合法动作、评分、理由
- 10 次连续运行/冒烟

**验收**：测试通过；无崩溃；非法动作 0。

### Day 7：演示与验收

- 5 分钟演示脚本
- 录制/截图
- 收集 3 人反馈
- 决定是否进入 B

**验收**：3/5 认为“有用”；至少 1 人认为“像队友”。

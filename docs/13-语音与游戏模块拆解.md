## 1. 语音模块：到底要做哪些部分

### 1.1 一句话目标

> 让 AI 的“建议/吐槽/复盘”能**在正确的时机、用正确的语气、以可接受的延迟**说出来，并且不干扰游戏音效、不刷屏、可随时静音/打断。

### 1.2 语音链路

```text
AI 文本（建议/吐槽/复盘）
  -> 语音策略：该不该说、现在说、说多长
  -> 文本清洗：去 Markdown / 动作 ID / 表格 / URL
  -> 台词生成：人格化、口语化、短句
  -> TTS：系统/云端，返回音频
  -> 播放队列：优先级、打断、静音、音量
  -> 字幕同步：显示与语音一致
  -> 日志/评估：延迟、失败、成本
```

### 1.3 工作拆解

| 编号 | 部分 | 具体要做什么 | 主 Owner | 验收 |
|---|---|---|---|---|
| V-01 | 语音策略 | 哪些事件说、哪些不说；战斗开始/结束、危险回合、选牌、玩家提问 | 马 | 不刷屏，关键节点有声音 |
| V-02 | 人格台词 | 人格卡、语气、口头禅、吐槽等级、边界 | 马 | 3 种语气可切换 |
| V-03 | 文本清洗 | 去 Markdown/代码/表格/URL/`c1@enemy`；长句切短 | 马 | 不朗读符号/乱码 |
| V-04 | 台词改写 | 把“预计掉血 7”改写成口语短句 | 马 | 自然、不伪造数值 |
| V-05 | TTS 适配层 | 统一 `SpeechProvider` 接口；系统/豆包/其他 | 胡 | 可替换 provider |
| V-06 | 系统 TTS | macOS `say` / Windows SAPI；中文语音检测 | 胡 | 本机能出声 |
| V-07 | 云端 TTS | 豆包/火山/其他 API；Key、voice ID、超时、重试 | 胡 | 返回音频可播放 |
| V-08 | 音频播放 | Godot/外部播放器；音量、静音、设备切换 | 胡 | 不卡主线程 |

| V-14 | 失败回退 | TTS 失败转字幕/静音；不阻塞游戏 | 胡 | 失败不崩 |
| V-15 | 合规 | AI 身份披露、声音授权、不克隆他人 | 马 + 胡 | 有说明 |

### 1.4 两个人怎么“一起写”

不建议“马写一半、胡写另一半然后拼起来”，建议按**接口**拆：

```text
马：SpeechContentPolicy / Persona / TextSanitizer
胡：TtsProvider / AudioPlayer / SpeechQueue
共同：SpeechPipeline 接口、联调、测试、验收
付：字幕 UI / 设置 UI
```

| 工作 | 马 | 胡 | 付 |
|---|---|---|---|
| 说什么/什么时候说 | **主** | 咨询 | 咨询 |
| 台词/人格 | **主** | 咨询 | 字幕风格 |
| 文本清洗 | **主** | 联调 | 显示 |
| TTS/音频 | 联调 | **主** | 设置 UI |
| 队列/打断 | 联调 | **主** | 按钮 |
| 字幕同步 | 咨询 | 联调 | **主** |
| 测试 | 共同 | 共同 | 验收 |

**共同交付物：**

- `SpeechPipeline` 接口（输入文本/优先级，输出播放状态）
- 一份“语音事件表”（什么事件、什么优先级、最大句长）
- 一套 mock TTS（离线测试，不依赖网络）
- 一份延迟/失败测试报告

### 1.5 语音 MVP 边界

先做：

- 字幕 + 系统 TTS
- 只朗读“建议/吐槽”短句
- 队列、静音、stop
- 不做 ASR（语音输入）
- 不做声音克隆
- 不做唇形同步

后做：

- 豆包/云端音色
- 流式按句合成
- 语音指令
- 情绪/语调变化

### 1.6 语音验收

- [ ] 关键节点能出声，不刷屏
- [ ] 不朗读 Markdown/动作 ID
- [ ] 语音可静音/打断
- [ ] 字幕与语音一致
- [ ] TTS 失败自动降级字幕
- [ ] 首包延迟 < 2 s（目标，实测记录）
- [ ] 不阻塞游戏主线程
- [ ] 不伪造数值/不人身攻击

## 2. 游戏模块：具体要实现哪些部分

### 2.1 总体数据流

```text
游戏状态
  -> State Adapter（标准化）
  -> 场景识别（战斗/奖励/商店/事件/地图）
  -> 决策模块（solver / 选牌 / 自动控制）
  -> 动作校验（合法/新鲜）
  -> 执行（游戏 API）
  -> UI/语音/日志
```

### 2.2 模块总表

| 编号 | 模块 | 要做什么 | 优先级 | 阶段 |
|---|---|---|---|---|
| G-01 | 游戏接入 | 读 `/state`、`/actions/available`；发 `/action` | P0 | A |
| G-02 | 状态适配 | 原始 JSON → 内部 `CombatState`/`RunState` | P0 | A |
| G-03 | 场景识别 | 战斗/奖励/商店/事件/地图/休息/宝箱 | P0 | A |
| G-04 | 合法动作 | 枚举手牌、目标、结束回合；索引校验 | P0 | A |
| G-05 | 战斗求解 | exact/beam/rollout；掉血/击杀线/备选 | P0 | A |
| G-06 | 抓牌评分 | top-1/top-3/skip；牌组协同/费用曲线 | P0 | A |
| G-07 | 建议展示 | 手牌索引、目标、预计掉血、理由 | P0 | A |
| G-08 | 自动打牌 | 循环执行、暂停/接管、失败恢复 | P1 | B |
| G-09 | 语音/字幕 | 语音策略、TTS、字幕 | P1 | B |

### 2.3 P0：A 观战搭子（先做）

#### G-01 游戏接入

- 读取 `GET /state`
- 读取 `GET /actions/available`
- 发送 `POST /action`（只读阶段可不发）
- 错误处理：连接失败/游戏不在战斗/状态过期

**验收**：能稳定读到当前手牌/敌人/奖励。

#### G-02 状态适配

- 手牌：ID/名称/费用/可打出/目标
- 玩家：HP/格挡/能量/遗物/药水
- 敌人：HP/格挡/意图
- 牌堆：抽/弃/消耗
- 场景：战斗/奖励/商店/事件/地图

**验收**：字段和游戏内一致；未知卡牌有降级。

#### G-03 场景识别

- `monster/elite/boss` → 战斗
- `card_reward/rewards` → 选牌
- `shop/event/map/rest/treasure` → 对应建议
- 其他 → 显示“暂不支持”

**验收**：不把奖励界面当战斗。

#### G-04 合法动作

- 手牌索引
- 目标索引
- EndTurn
- 药水/其他（后续）

**验收**：建议动作 100% 在合法列表内。

#### G-05 战斗求解

- exact 当前回合穷举
- beam 对比
- rollout 2 回合诊断
- 输出：动作/目标/预计掉血/敌方 HP/击杀

**验收**：固定 fixture 结果稳定；延迟可接受。

#### G-06 抓牌评分

- 三选一排序
- skip
- 依据：卡牌强度、牌组协同、费用曲线、Act/Boss
- 输出 top-1 + 2–3 条理由

**验收**：理由引用具体卡牌/数值。

#### G-07 建议展示

- 手牌列表 `[0]…[4]`
- 推荐动作 + 索引 + 目标
- 备选 top-3
- 预计掉血/敌方 HP
- 理由/警告

**验收**：一屏能看懂；不要求用户读 JSON。

#### G-11 配置/诊断

- Endpoint/Base URL
- Model
- API Key
- 连接测试（含 tool calling）
- 日志/错误提示

**验收**：配置失败能说清原因。

#### G-12 评估/回归

- 固定战斗 fixture
- exact/beam/rollout 对比
- 10 场实机冒烟
- 非法动作/崩溃/延迟记录

**验收**：每次改动有回归结果。

### 2.4 P1：B 自动打牌/语音

#### G-08 自动打牌

- 开始/单步/暂停/继续/接管
- 战斗、奖励、商店、事件、地图、休息、宝箱
- 执行前校验快照
- 失败熔断/超时/预算
- 决策日志

**验收**：10 场不崩；非法动作 0；可随时停。

#### G-09 语音/字幕

见第 1 节。

### 2.5 P2：C AI 第二队友

#### G-10 双人 co-op

- 拉起第二实例/加入本地大厅
- AI 只操作自己的角色
- 地图投票/目标协同
- 团队聊天
- 暂停/继续/异常恢复
- 存档隔离/备份

**验收**：10 场 co-op 不坏档；不替人类出牌；可暂停。

### 2.6 本期不做什么

- 全角色全卡池
- 全自动通关
- 排行榜/成就
- 云端账号
- 声音克隆
- 自研游戏引擎/双实例底座
- 复杂 Mod 生态兼容（先支持最小集合）

## 3. 模块依赖与开发顺序

```text
G-01 接入
  -> G-02 状态
  -> G-03 场景
  -> G-04 合法动作
  -> G-05 战斗 / G-06 选牌
  -> G-07 展示
  -> G-08 自动 / G-09 语音
  -> G-10 双人
```

建议顺序：

1. G-01/02/03：先能读
2. G-04/05/06：先能算
3. G-07：先能看
4. G-08/09：再能打/能说
5. G-10：最后双人

> 不要先做 G-10：co-op 的坑最多，容易把前四步拖死。

## 5. 验收口径

### 语音

- 该说时能说，不该说时闭嘴
- 不朗读符号/动作 ID
- 可静音/打断
- 字幕一致
- 失败不阻塞游戏

### 游戏

- 建议合法
- 状态正确
- 选牌有理由
- 自动打可暂停
- 双人可停/不坏档

> 先保“合法 + 有用”，再保“像队友”，最后才保“双人”。

# 待办：攻略与角色知识库

日期：2026-10-28  
目标：让模型基于**玩家自己的攻略**做选牌、遗物、商店、药水等局外决策，而不是靠泛化印象。  
状态：待排期（先记录，不动代码）。

---

## 1. 边界

- 知识库只吃"当前局面 + 候选 + 攻略片段"，输出**排序/推荐/理由**；
- 不读游戏对象、不点按钮、不出牌；
- 战斗出牌仍归 CombatSolver，攻略只影响"选什么/买什么/走哪"。

---

## 2. 攻略数据的组织

建议目录：

```text
docs/guides/<character>/
├── 00-overview.md
├── 10-card-tier.md
├── 20-archetypes.md
├── 30-relics.md
├── 40-shop.md
├── 50-early-game.md
└── 60-boss-notes.md
```

每个文件带元信息（角色、主题、标签、**适用的进阶区间**），正文按卡名/遗物名分节，便于精确检索。

---

## 3. 关键问题：A0 与 A8 的卡池不同（本轮新增）

角色在 **A0** 与 **A8** 下可获得的卡牌不同，攻略与决策必须区分，不能共用一份。

必须处理：

1. **快照补字段**：`GameSnapshot` 增加 `AscensionLevel`（游戏侧 `RunState.AscensionLevel`），并计入指纹；
2. **候选来源区分**：选牌候选、商店卡牌、事件给的牌都要按当前进阶过滤/标注，不能把 A0 的卡当成 A8 的可用卡；
3. **攻略分层**：
   - 攻略文件按 `ascension` 元信息标注（如 `ascension: [0-7]`、`ascension: [8+]`）；
   - 检索时只取当前进阶适用的片段；
   - 缺失对应进阶攻略时，**明确降级**（用通用片段 + 提示"当前进阶无专门攻略"），不能静默套用 A0 结论；
4. **不止卡牌**：进阶还可能改变遗物、敌人、事件、Boss 行为；需要先确认差异清单，再决定攻略要不要按进阶拆文件；
5. **可维护**：差异清单不要硬编码在代码里，能从游戏数据/卡池读取的就读取，攻略侧只存"建议"。

**待确认**：A8 具体差异清单（哪些卡被移除/替换、遗物/事件是否也变），需要用户提供或从游戏数据提取后核对。

---

## 4. 检索与决策方式

| 阶段 | 做法 | 工期 |
| --- | --- | --- |
| 1 | 目录扫描 + 卡名/遗物名索引 + 热加载；决策时取 1–2 段相关攻略拼进 prompt | 2–3 天 |
| 2 | 每角色/进阶的结构化 tier 表与阈值规则（护栏 + 初筛） | 1 周 |
| 3 | 本局计划记忆（流派、核心牌、还缺什么）+ 决策日志/复盘 | 3–5 天 |

原则：

- 每次只注入相关片段（几百字），按卡名精确命中，不整篇塞；
- 选牌/商店优先用结构化规则，RAG 处理长尾，模型做解释与最终选择；
- 记录"引用了哪段攻略"，方便复盘。

---

## 5. 多角色

- 知识库按角色分目录；决策时按 `snapshot.Character` 选库；
- 没有对应角色攻略时，回退到通用规则并提示；
- 角色专属机制（能量、牌堆、姿态等）在攻略元信息里标注。

---

## 6. 评估

- 每次决策记录：候选、选择、引用片段、理由；
- 每局结束记录：牌组、胜负、死因；
- 每周抽样回看，区分"攻略没覆盖""检索错""模型没听懂""规则太硬"。

---

## 7. 其他注意

- 攻略若来自网络，建议改写为要点或只存摘要，避免版权问题；
- 攻略文件支持运行中热加载，改文件不用重启游戏；
- token 预算：单次决策注入 ≤ 800 字，超出截断并优先卡名命中部分。

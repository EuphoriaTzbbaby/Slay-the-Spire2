# 待办：攻略与角色知识库

日期：2026-10-28  
目标：让模型基于**玩家自己的攻略**做选牌、遗物、商店、药水等局外决策，而不是靠泛化印象。  
状态：待排期（先记录，不动代码）。

---

## 1. 边界

- 知识库只吃"当前局面 + 候选 + 攻略片段"，输出**排序/推荐/理由**；
- 不读游戏对象、不点按钮、不出牌；
- 战斗出牌仍归 CombatSolver，攻略只影响"选什么/买什么/走哪"。

---

## 2. 攻略数据的组织

建议目录：

```text
docs/guides/<character>/
├── 00-overview.md
├── 10-card-tier.md
├── 20-archetypes.md
├── 30-relics.md
├── 40-shop.md
├── 50-early-game.md
└── 60-boss-notes.md
```

每个文件带元信息（角色、主题、标签、**适用的进阶区间**），正文按卡名/遗物名分节，便于精确检索。

---

## 3. 关键问题：进阶（A0/A8）对决策的影响

背景：用户反馈"A0 和 A8 的卡牌不同"。核对游戏程序集后，先记录事实：

游戏内 `AscensionLevel` 共 11 档（0–10），名称如下：

| 等级 | 枚举名 | 大意 |
| --- | --- | --- |
| 0 | None | 无进阶 |
| 1 | SwarmingElites | 精英更多 |
| 2 | WearyTraveler | 敌人伤害提高 |
| 3 | Poverty | 金币更少 |
| 4 | TightBelt | 药水/资源更紧 |
| 5 | AscendersBane | 开局带诅咒 |
| 6 | Inflation | 商店更贵 |
| 7 | Scarcity | 资源更稀缺 |
| 8 | **ToughEnemies** | **敌人生命提高** |
| 9 | DeadlyEnemies | 敌人伤害再提高 |
| 10 | DoubleBoss | 双 Boss |

**结论（待实机核对）**：A8 本身是"敌人更肉"，枚举里没有"改卡池"这一项；`AscensionHelper` 只是按等级取不同数值。因此"A0/A8 卡牌不同"更可能指**该拿什么牌/该怎么打不同**（策略差异），而不是候选池不同。

据此调整设计：

1. **候选不过滤**：选牌/商店候选以游戏实际给出的为准，不按进阶人为过滤，除非实机验证到某张牌/遗物确实随进阶出现或消失；
2. **进阶作为策略上下文**：快照补 `AscensionLevel`（`RunState.AscensionLevel`），传给规则/模型，影响排序、阈值与提示；
3. **攻略按进阶分层**：同一角色可写"A0–A7 建议"和"A8+ 变化"；检索时优先当前区间，没有则明确降级，不静默套用；
4. **可维护**：差异清单从游戏数据读取/核对，不硬编码；
5. **待确认**：如果用户能举出"A8 确实少了/多了某张牌"的具体例子，再从游戏数据核查卡池与解锁条件，确认后改为候选过滤。

## 4. 检索与决策方式

| 阶段 | 做法 | 工期 |
| --- | --- | --- |
| 1 | 目录扫描 + 卡名/遗物名索引 + 热加载；决策时取 1–2 段相关攻略拼进 prompt | 2–3 天 |
| 2 | 每角色/进阶的结构化 tier 表与阈值规则（护栏 + 初筛） | 1 周 |
| 3 | 本局计划记忆（流派、核心牌、还缺什么）+ 决策日志/复盘 | 3–5 天 |

原则：

- 每次只注入相关片段（几百字），按卡名精确命中，不整篇塞；
- 选牌/商店优先用结构化规则，RAG 处理长尾，模型做解释与最终选择；
- 记录"引用了哪段攻略"，方便复盘。

---

## 5. 多角色

- 知识库按角色分目录；决策时按 `snapshot.Character` 选库；
- 没有对应角色攻略时，回退到通用规则并提示；
- 角色专属机制（能量、牌堆、姿态等）在攻略元信息里标注。

---

## 6. 评估

- 每次决策记录：候选、选择、引用片段、理由；
- 每局结束记录：牌组、胜负、死因；
- 每周抽样回看，区分"攻略没覆盖""检索错""模型没听懂""规则太硬"。

---

## 7. 其他注意

- 攻略若来自网络，建议改写为要点或只存摘要，避免版权问题；
- 攻略文件支持运行中热加载，改文件不用重启游戏；
- token 预算：单次决策注入 ≤ 800 字，超出截断并优先卡名命中部分。

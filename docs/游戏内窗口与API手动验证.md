# 游戏内窗口与 API 手动验证

## 当前可以做什么

已经实现游戏内文字对话窗口。填写兼容 Chat Completions 的服务地址、模型名和 API Key 后，可以手动测试模型连接、发送消息，或请求分析当前局面。聊天不需要先开启托管，也不会执行出牌、购物或用药。

本轮已完成编译与本地模拟接口检查，未替用户调用真实服务或启动游戏。下面的步骤用于实际验收。

## 打开窗口

1. 完全退出游戏后重新启动，让新版 DLL 生效。
2. 在游戏 Mod 管理中启用“尖塔 AI 陪玩（开发版）”，模块 ID 为 SpireCompanion。
3. 点击左上角“AI 搭子”，或按 F9。Mac 若将 F9 用作系统功能键，可以尝试 Fn+F9，或直接使用按钮。
4. 默认打开“聊天与 API”页签；“游戏状态与控制”页签用于状态查看和手动控制。
5. 可拖动窗口标题栏，或点击关闭；关闭只隐藏窗口，不退出游戏。较长内容可以滚动查看。

## 配置与测试

| 字段 | 填什么 |
| --- | --- |
| API 地址 | 服务商提供的基础地址，如 https://服务地址/v1；也可填完整 /chat/completions 地址。 |
| 模型名称 | 当前账号有权限调用的准确模型名称。 |
| API Key | 对应服务的密钥。默认遮挡；解锁本地档案后勾选记住并保存，写入该档案的加密文件。 |
| 回复风格 | 安静、普通或话多，目前控制回复语气和长度。 |

点击“测试 API 连接”。测试通过实际 Chat Completions 短请求验证地址、授权、模型调用及文字响应，不是只检测网络是否连通；可能产生少量服务商费用。不发送真实游戏快照，也不写入聊天历史。

成功提示：“连接及模型调用成功（耗时），现在可以发送消息。”

默认地址为 https://api.deepseek.com，默认模型为 deepseek-flash，旧的非空自定义值会保留。

先创建或解锁本地档案，勾选“记住 API Key”并点击“保存设置”，API Key 写入跨平台加密文件。启用本机自动解锁后，系统仅保存文件解密凭据，下次自动加载；档案密码可用于手动解锁。直接测试不等于保存。取消勾选后保存会删除该档案中该服务的密钥。

系统可能要求钥匙串授权，失败时界面提示且不会改用明文文件。环境变量 SPIRE_COMPANION_API_KEY 仍可提供会话密钥。更换服务域名时清空输入框，避免把原服务密钥发送给其他服务。保存设置不会调用模型。

## 对话验收

1. 输入“你好，介绍一下自己”，点击发送或按回车。
2. 确认搭子返回中文文字。
3. 继续追问，确认有短期上下文。
4. 请求过程中点击取消，确认不再显示该条旧回复；也可清空已完成的对话。
5. 进入跑局后点击“分析当前局面”，确认能结合当前角色与资源回答。

主菜单也能聊天和测试连接；主菜单没有战斗状态，因此不能据此评价战斗建议质量。奖励、商店、地图等完整选项尚未接入，不能期望当前版本准确推荐未提供的选项。

局面在请求期间变化时，界面会提示建议基于提问时状态。测试聊天时不用点击“启用手动操作”或启动 CombatSolver。存在其他自动控制 Mod 时，本模块的操作限制不妨碍纯文字测试。

## 常见结果

| 提示 | 优先检查 |
| --- | --- |
| HTTP 401 | 密钥错误、过期或不属于该服务。 |
| HTTP 403 | 密钥无权调用该服务或模型。 |
| HTTP 404 | 基础地址、接口路径或模型名错误。 |
| HTTP 429 | 请求频率、账户额度或服务商限制。 |
| 响应超时 | 网络、服务负载或模型响应速度；默认等待 45 秒。 |
| 未返回可显示文字 | 服务协议或返回格式不兼容；当前不支持仅 Responses 的接口。 |
| 没有窗口 | 是否彻底重启、启用正确 Mod，或窗口被隐藏；检查游戏日志中的 SpireCompanion 初始化记录。 |

反馈问题时提供错误文字、是否在主菜单、模型名和地址路径即可；不要把 API Key、授权头或未遮挡密钥的截图发到聊天或 GitHub。

## ReflectionTypeLoadException 加载问题修复

真实启动日志显示游戏在调用 Mod 初始化之前扫描类型，旧主 DLL 此时依赖的 SpireCompanion.Core 尚未被解析。已改为将同一份核心源码直接编译进 SpireCompanion.dll，不再通过初始化函数延迟注册核心程序集。

当前安装文件为 SpireCompanion.dll、SpireCompanion.json 和 LICENSE；旧 Core DLL 由安装脚本备份后移除。已通过旧 DLL 负例和新 DLL 依赖检查，用户需要完全退出游戏并重启加载新版；不能在当前进程中热更新。

## 面板返回值 Variant 异常修复

离线加载日志曾出现 `The type is not supported for conversion to/from Variant: 'SpireCompanion.CompanionPanel'`：面板延迟创建使用了返回 `CompanionPanel` 的 lambda，Godot 会尝试把返回值转成 Variant 并抛异常。面板本身仍能创建，但每次启动都会留下一条 ERROR，容易与真实故障混淆。

已改为不返回值的 lambda；`scripts/game_smoke.py` 的失败特征中加入该异常文本，避免同类问题再次漏过。2026-10-27 重新构建并在独立副本中加载：入口初始化、`PANEL_READY`、中文字体就绪和主菜单状态读取通过，日志中不再出现 Variant 异常，仅剩无头渲染的退出期资源警告。已重新安装到游戏目录，仍需完全重启游戏才生效。

## 中文字体显示修复

用户截图中入口“AI 搭子”的中文显示方框：入口按钮是窗口的同级节点，未继承窗口的中文字体。已让入口与窗口共享中文主题，并显式设置按钮、标签、输入框、页签、菜单和提示文字字体。编译安装后需重启游戏观察效果；没有把未观察到的显示结果标为通过。

当前存储方案以 [本地加密与账户档案说明](APIKey本地加密存储与账户档案.md) 为准，旧系统密钥不会擅自删除，可手动导入。

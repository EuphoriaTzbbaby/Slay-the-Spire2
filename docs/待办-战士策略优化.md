# 待办：铁甲战士策略优化

日期：2026-10-30
状态：**未开始**
分支：`feat/warrior-strategy-optimization`（已推送至 fork `cdwswb/Slay-the-Spire2`）

## 1. 背景

角色策略已数据化：每个角色一份 `Characters/*.json` 档案，按当前角色注入聊天提示词与自动决策，支持 `user://spire-companion/characters` 热加载（见 [协作-分支与合并](协作-分支与合并.md)、[待办-角色差异化建议](待办-角色差异化建议.md)）。

当前 `ironclad.json` 过于单薄：仅 4 个字段各 2–3 条规则，没有流派区分，远低于 [待办-决策策略化](待办-决策策略化.md) 中 D1 阶段对铁甲的预期（力量、格挡/壁垒、消耗、狂怒流血等多个流派）。

**修正记录**：自动战斗已不再限定铁甲。`SolverBridge.CanStart` 已移除角色硬编码，由 CombatSolver 判断角色支持；CombatSolver 侧已覆盖全部可玩角色。因此战士策略优化与其他角色策略优化属于**并行竞争关系**（都影响建议质量），不再是"唯一能自动战斗的角色"这一独占价值，但仍按一个角色一个分支、一个 PR 的规范推进。

## 2. 目标

在不改动任何 `.cs` 文件的前提下，把 `ironclad.json` 充实为流派化、可验证的策略档案，使同一局面下战士的选牌/战斗/商店建议明显区别于通用话术。

## 3. 分阶段任务

### W1 充实 JSON 档案（核心，零代码改动）

- `mechanics`：补全机制词（燃烧之血战后回血、力量永久叠加、重锤/自伤类代价、易伤联动、消耗机制等，以当前版本为准）；
- `draft`：按流派写选牌规则——力量流（叠力量/多段攻击）、格挡壁垒流（缺防御时优先）、消耗流（注意牌组厚度）、狂怒流血流；含费用曲线与"跳过"取舍；
- `combat`：力量窗口集中输出、易伤联动、有燃烧之血容错时可主动换血；
- `shop`：删打击时机、力量核心卡/遗物预算、药水取舍。

数据来源：游戏数据（ModelDb 卡牌/遗物真实效果）+ 玩家攻略 + 实战复盘。

### W2 热加载实测

- 修改后的 JSON 放入 `user://spire-companion/characters/` 覆盖内置档案；
- 验证：同一局面、战士与其他角色的建议措辞与取舍应不同；改文件无需重启即生效。

### W3（可选）扩展档案 schema

- 如需覆盖休息点/遗物/路线建议，给 `CharacterProfileData` 增加可选字段（如 `rest`、`route`）；
- 涉及共享文件 `CharacterProfiles.cs`，改动前先在群里知会；新字段必须可选，旧 JSON 不填不报错；
- 尽量与其他角色的同类需求合并成一次改动，减少冲突。

### W4（加分项）攻略知识库与回归

- 按 [待办-攻略与角色知识库](待办-攻略与角色知识库.md) 补 `docs/guides/ironclad/`（卡牌优先级、战斗、商店、路线）；
- 按 [待办-决策策略化](待办-决策策略化.md) D5 建立战士各流派金样例（golden cases），改动后推荐结果必须一致或有意更新。

## 4. 验收

- `ironclad.json` 覆盖至少 3 个明确流派，选牌规则可区分流派契合度；
- JSON 格式校验通过，热加载与内置加载均正常；
- 不修改任何 `.cs`（W3 若立项则单独分支、单独 PR）；
- 同一局面对比优化前后，建议中的机制词与取舍明显不同；
- PR 只包含 `ironclad.json`（及对应文档），与其他角色的 JSON 改动不冲突。

# 待办：按角色给出不同的游戏建议

日期：2026-10-28  
目标：同一个 AI 陪玩，在铁甲战士、静默猎手、故障机器人等不同角色下，给出**符合该角色机制**的选牌、战斗、商店、路线建议，而不是一套通用话术。  
状态：阶段 1 完成（2026-10-29）：角色档案改为 `Characters/*.json` 数据文件，按当前角色注入聊天与自动决策；支持 `user://spire-companion/characters` 热加载；队友只需新增 JSON，见 [协作-分支与合并](协作-分支与合并.md)。

---

## 1. 现在的问题

- 快照里只有 `Character` 名称，提示词没有人格/机制差异；
- 模型靠训练记忆区分角色，容易把某角色的打法套到另一个角色；
- CombatSolver 桥接目前只允许铁甲战士（`SolverBridge.CanStart` 检查 `IRONCLAD`），其他角色战斗没有自动执行；
- 没有任何"角色机制说明"进入上下文。

---

## 2. 方案：角色档案（Character Profile）

每个角色一份结构化档案，代码按 `snapshot.Character` 选择：

```json
{
  "id": "IRONCLAD",
  "name": "铁甲战士",
  "mechanics": ["力量", "易伤", "自伤", "消耗"],
  "draft_rules": [
    "优先拿能叠力量的牌",
    "牌组 28 张以上少拿普通攻击",
    "缺格挡时优先防御类"
  ],
  "combat_notes": [
    "有力量时优先多段攻击",
    "易伤窗口内集中输出"
  ],
  "shop_rules": ["优先删打击", "力量核心牌可以买"],
  "relic_synergy": ["燃烧之血：战后回血，容错高"]
}
```

注入方式：

1. **系统提示**追加该角色的 `mechanics + draft_rules`（约 150–300 字）；
2. **当前界面**再叠加 `ScreenGuidance`（奖励/商店/休息/战斗）；
3. **自动决策**把角色档案放进 `run_plan` 同级字段，模型选 id 时参考；
4. 未知角色 → 只用通用规则，并提示"暂无该角色专门建议"。

---

## 3. 内容从哪来

| 来源 | 用途 |
| --- | --- |
| 游戏数据（`ModelDb`） | 卡牌/遗物/药水的真实效果，已有 |
| 玩家攻略 | 角色机制、流派、取舍，按角色分文件 |
| 实战复盘 | 每局记录选牌与结果，逐步修正规则 |
| CombatSolver 适配 | 战斗执行只支持求解器支持的角色 |

攻略文件建议：

```text
docs/guides/<character>/
├── 00-overview.md      # 机制与流派
├── 10-card-tier.md     # 卡牌优先级
├── 20-combat.md        # 战斗要点
├── 30-shop.md          # 商店/删牌
└── 40-route.md         # 路线偏好
```

支持热加载：改文件不用重启游戏。

---

## 4. 与战斗求解器的关系

- `SolverBridge.CanStart` 现在硬编码铁甲战士；
- 其他角色要么等 CombatSolver 提供适配，要么只给文字建议、不自动打；
- 角色档案不能假装能自动战斗，必须在界面上说明"该角色战斗暂不支持自动执行"。

---

## 5. 分阶段

| 阶段 | 内容 | 工期 |
| --- | --- | --- |
| 1 | 角色档案数据结构 + 按角色注入系统提示（先铁甲/静默/机器人） | 2–3 天 |
| 2 | 每角色每界面规则（奖励/商店/休息/战斗） | 3–5 天 |
| 3 | 攻略文件热加载 + 检索注入 | 2–3 天 |
| 4 | 每局记录与角色规则复盘 | 3–5 天 |

---

## 6. 验收

- 同一局面、不同角色，建议中的机制词和取舍应不同；
- 未知角色不硬套铁甲打法；
- 非铁甲角色不会错误尝试自动战斗；
- 指南文件更新后无需重启即可生效（阶段 3）。

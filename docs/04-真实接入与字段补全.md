## 1. 前置条件

- 《杀戮尖塔 2》EA 桌面版（Steam），建议记录具体版本，例如公开基准使用的 `v0.107.1`。
- BaseLib（StS2 版本）。
- `Communication_Mod_STS2`（本地 mod，未见明确许可证，不要在项目中再分发）。
- Python 3.11+；本项目无第三方运行依赖。

安装顺序：

1. 把 BaseLib 的 `.dll/.pck/.json` 放进 `mods` 目录。
   - Windows/Linux：`steamapps/common/Slay the Spire 2/mods`
   - macOS：`SlayTheSpire2.app/Contents/MacOS/mods`（右键 app → 显示包内容）
2. 把 `Communication_Mod_STS2` 的 `Communication_Mod` 文件夹放进同一个 `mods` 目录。
3. 启动游戏，确认两个 mod 已启用。
4. **不要同时运行上游 `server.py` 与本项目 `capture`/`serve`**，它们都占用 `127.0.0.1:5000`。

## 2. D1：先抓状态，不决策

```bash
cd "<项目根目录>"
make capture
# 或
PYTHONPATH=src python3 -m spirepilot capture --port 5000 --session d1
```

操作：

1. 进入一场普通战斗。
2. 打 2–3 个回合（可以故意打一张格挡牌）。
3. 进入一次卡牌奖励界面。
4. Ctrl-C 停止。

产物：

```text
data/replays/d1/
├── states.jsonl   # 每条：ts / trigger / kind / raw
└── meta.json      # 计数、开始时间、最后 trigger
```

`capture` 只记录并回 `OK`，不会执行任何动作。

## 3. D2：审计字段

```bash
# 审计最后一条状态
PYTHONPATH=src python3 -m spirepilot inspect \
  --capture data/replays/d1/states.jsonl --index -1

# 审计某一条（从 0 开始）
PYTHONPATH=src python3 -m spirepilot inspect \
  --capture data/replays/d1/states.jsonl --index 3

# 机器可读
PYTHONPATH=src python3 -m spirepilot inspect \
  --capture data/replays/d1/states.jsonl --index -1 --json
```

审计报告会区分：

- `OK`：字段存在。
- `WARN`：缺字段，但可以降级运行（例如 `Player.Block` 缺失）。
- `MISS`：缺关键字段，无法建议。
- 结论：`ready` / `degraded` / `blocked` / `non_combat`。

### 需要重点确认的字段

| 字段 | 为什么重要 | 当前情况 |
|---|---|---|
| `Player.Block` | 决定本回合还要不要格挡、能否省下攻击 | 上游导出代码中未见 |
| `Enemies[].Block` | 决定斩杀线 | 上游导出代码中未见 |
| 手牌 `Cost` | 合法动作/能量规划 | 手牌只有 `Card_Name`/`Card_ID` |
| 手牌 `CanPlay` | 条件卡是否可打出 | 未见 |
| 手牌 `IsUpgraded` | 升级牌数值 | 未见 |
| `CardCatalog` | 费用/伤害/格挡/目标 | 有，但字段有限 |
| `FirstInfo.RunStatus` | 角色/Act/Floor | 通常有 |
| 游戏版本 | 复现 | 状态本身没有，需要外部记录 |

## 4. D3：补字段（本地 patch，不再分发）

如果审计显示 `Player.Block` / 手牌费用仍缺失，建议在本地 fork 的 `MainFile.cs` 中补：

1. **玩家格挡**：在 `Player` 匿名对象里增加 `Block`（示意：`Block = playerCreature.Block`）。
2. **手牌详情**：把 `Piles.HandPile` 的投影从「只有 `Card_Name`/`Card_ID`」扩展为同时包含：
   - `Cost`（`EnergyCost.CostsX ? "X" : EnergyCost.GetResolved()`）
   - `IsUpgraded`
   - `CanPlay` / 可打出标志
   - `TargetType`
3. **敌人格挡**：在 `Enemies` 投影中增加 `Block`。
4. **卡牌文本/类型/稀有度**（可选）：在 `CardCatalog` 中补 `Type`、`Rarity`、`Text`，便于解释和后续选牌。

> 这些属性名需要按当前 `sts2.dll` 版本编译验证；上面的写法是**位置示意**，不是可直接套用的补丁。上游 mod 无明确许可证，补丁只本地保存，不进入本项目仓库、不再分发。

补完后重新跑 `inspect`，目标是：

```text
结论：ready
Player.Block OK
手牌 Cost OK
手牌 CanPlay OK
敌人 Block OK
```

## 5. 影子状态（补丁前的降级方案）

如果暂时不能改 mod，可以在 bridge 侧维护一个「影子格挡」：

- `OnTurnStarted`：格挡归 0（除非 Barricade/保留效果）。
- 收到 `PlayCard` 后：如果下一状态确认手牌减少，按卡牌格挡值累加。
- 敌方回合后：按意图伤害扣减/清零。

这只适合做近似建议，不能替代真实 `Block` 字段；不要用它做正式胜率结论。

## 6. Golden trace

拿到真实状态后，可以构造 trace：

```json
{
  "name": "real_combat_001",
  "game_version": "0.107.1",
  "initial_state": { "...": "..." },
  "steps": [
    {
      "action": {"Type": "PlayCard", "HandIndex": 2, "TargetIndex": 0},
      "expected_state": { "...": "..." }
    }
  ]
}
```

运行：

```bash
PYTHONPATH=src python3 -m spirepilot trace --trace data/traces/real_combat_001.json
```

对比项：玩家 HP/格挡/能量、敌人 HP/格挡、能力、手牌/抽牌/弃牌/消耗多重集、回合数。
缺失的字段会跳过并给 warning，不会假装对比过。

## 8. 常见问题

**Q：capture 和 serve 能同时开吗？**
不能，端口冲突。先 capture 抓数据，再 serve 做建议/自动。

**Q：为什么 capture 回 `OK`？**
mod 会把响应体当命令；`OK` 是安全的无动作响应。capture 不应该执行动作。

**Q：为什么 inspect 结论是 `degraded` 但还能给建议？**
因为 `Block`/手牌费用等字段缺失时，advisor 会按 0/静态库估算并输出警告。`degraded` 表示「能用但精度有限」，不是「不能用」。

**Q：真实游戏是 macOS 版可以吗？**
需要在 D1 验证 mod 是否加载；当前项目未验证 macOS 兼容性。若不兼容，换 Windows 环境或先做离线回放。
